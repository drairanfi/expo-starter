# Critical constraints (read first)

Hard rules. Breaking one means the change is wrong, whatever else works.

1. **Dependency direction.** `presentation -> domain <- data`; both use `src/core`.
   `domain` is pure TypeScript: no React, `react-native`, `expo-*`, axios, storage or
   network imports. `src/core` never imports `@/features` or `@/shared`. ESLint enforces it
   (`no-restricted-imports` in `eslint.config.js`).
2. **Features expose a public `index.ts`.** Other features and `src/app` import only
   `@/features/<name>`, never `@/features/<name>/data|domain|presentation/...`. Inside a feature use
   relative imports. Share through a domain type or promote the code to `core/` or `shared/`.
3. **`src/shared/components` is feature-agnostic.** It never imports `@/features`.
4. **Route files in `src/app` are thin.** They re-export a feature screen or lay out a
   navigator. No data fetching, forms or business rules there. The auth guard lives only in
   `src/app/_layout.tsx` (`Stack.Protected`).
5. **No business logic in components.** Components render state and call hooks. Rules, mapping
   and I/O live in domain, data or hooks.
6. **Server state in TanStack Query, client state in Zustand.** Never copy query data into a store.
7. **Errors are `Failure`s.** Repositories throw `FailureError`; the UI shows
   `useLocalizedError()`, never `Failure.message`. 401s end the session through
   `setUnauthorizedHandler`, registered by `src/app/_layout.tsx`; `core` stays feature-free.
8. **Validate every API payload with Zod** (`parseResponse(schema, data)`). Types come from
   `z.infer`, not hand-written duplicates.
9. **No hard-coded user-facing strings.** Add keys to both `src/core/i18n/locales/en.ts` and
   `es.ts` and use `t('...')`.
10. **No raw colors, spacing or font sizes in features/components.** Use `useTheme()` tokens from
    `src/core/theme/tokens.ts`.
11. **No secrets in the repo or the bundle.** Anything `EXPO_PUBLIC_*` ships in the app and is
    public. Never read or edit `.env.<variant>`, keystores, `google-services.json`,
    `GoogleService-Info.plist`, `.p12`, `.mobileprovision`, `.pem`, `credentials.json`. The
    `.env.*.example` files are the only tracked env files.
12. **Never commit `ios/` or `android/`.** They are generated by `expo prebuild` from
    `app.config.ts` (CNG). Change config, not native folders.
13. **Variants.** `APP_VARIANT` selects `development|staging|production`. Identity (name, ids,
    scheme) derives from `app.config.ts`; never hand-edit bundle ids. Its Zod schema is a copy of
    `src/core/config/schema.ts`; change both and keep `tests/core/config/app-config-file.test.ts` green.
14. **TypeScript strict, no `any`.** No `@ts-ignore`; use `@ts-expect-error` with a reason only
    when unavoidable. Use `import type` (`consistent-type-imports`).
15. **No `console.*`.** Use `logger` from `@/core/utils` (the one sanctioned user).
16. **Generated and lock files are never hand-edited:** `package-lock.json`, `expo-env.d.ts`,
    `.expo/`, `dist/`, `coverage/`. Use `npm install` / `npx expo install`.
17. **No new dependency without asking.** Add Expo-compatible packages with `npx expo install`.
18. **Identifiers, comments and docs are English.**
19. **Done means green:** `npm run typecheck`, `npm run lint`, `npm run format:check`, `npm test`
    (`npm run verify`).
