# i18n

- i18next + react-i18next. Resources are bundled and typed: `en.ts` is the source of truth,
  `es.ts` must satisfy its shape (`tests/core/i18n/locales.test.ts` checks parity). Keys are
  type-checked through `src/core/i18n/i18next.d.ts`.
- Every user-facing string is `t('area.key')` via `useTranslation()`. No literals in JSX,
  props (`accessibilityLabel`, `placeholder`), alerts or navigator titles.
- Add a key to **both** `en.ts` and `es.ts` in the same change. Use interpolation
  (`t('home.welcome', { name })`), never string concatenation.
- Nested `camelCase` keys grouped by area; shared groups: `errors`, `validation`, `a11y`, `theme`.
- Dynamic keys from domain code (Zod messages, `failureMessageKey`) are i18n keys; translate
  at the UI boundary (`useLocalizedError`, `t(message as never)` only in forms, as in `login-screen.tsx`).
- Language follows the device (`detectLanguage()`, fallback `en`); there is no in-app picker.
- A new language: add `locales/<code>.ts`, extend `SUPPORTED_LANGUAGES` and `resources`.
- Tests assert English text.
